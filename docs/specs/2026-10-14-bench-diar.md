# Стенд диаризации на реальных сессиях — спецификация (тикет 02)

Главная жалоба по логу качества — диаризация склеивает людей и дробит одного человека на несколько «Speaker N».
Менять пороги вслепую нельзя: нужна метрика на реальных встречах. Эталона разметки нет, но есть плитки Толка:
`talk.jsonl` говорит, кто подсвечен говорящим в каждый момент, и это независимая от голоса правда.

## Что считаем

Команда `transcriber bench-diar` читает **уже записанные** сессии из каталога данных (`sessions/<id>/`): `state.json`
(эмбеддинги sys-канала и реплики) и `talk.jsonl`. Аудио и модели не нужны: перекластеризация идёт по сохранённым
эмбеддингам текущим конфигом (`speaker_similarity`, `absorb_small_clusters`) — ровно как `refinalize`.
Сессии только читаются; результат ложится в `bench/diar/runs/NN-<label>/` рядом со стендом `bench`.

Для каждой сессии:

- **размеченные реплики** — sys-реплики с эмбеддингом, которым `speaker_for_span` (тот же порог `MIN_SHARE`,
  те же шаблоны переговорок, ботов и общих микрофонов из конфига) даёт имя плитки; остальные в метрику не входят;
- **чистота** (purity) — доля размеченных реплик, чьё имя совпадает с именем большинства в их кластере
  (1.0 — ни один кластер не смешивает людей);
- **цельность** (completeness) — доля размеченных реплик, попавших в главный кластер своего имени
  (1.0 — ни один человек не разбит на несколько кластеров);
- **склейки** — кластеры, где у двух имён покрытие ≥ 0.3 каждое (критерий тикета 04);
  **расколы** — имена, у которых ≥ 0.3 реплик лежат вне главного кластера;
- **кластеров / говоривших** — число голосовых кластеров против числа людей, которым плитки дали хотя бы одну реплику
  (в `metrics.json` ещё и число всех людей на плитках без переговорок и ботов — молчавшие кластеров не образуют).

Веса — по числу реплик (не по секундам): стенд ищет ошибки разметки, а не громкость. Итог по прогону —
взвешенно по размеченным репликам всех сессий, плюс число сессий, реплик и сумма склеек/расколов.

## Отбор сессий

По умолчанию все неприватные сессии с `talk.jsonl`, у которых ≥ 20 размеченных реплик и ≥ 2 имени
(сессия с одним собеседником ничего не говорит о склейках). Флаги: `--min-labeled N`, `--min-names N`,
`--since YYYY-MM-DD`, `--sessions id,id`. Список вошедших сессий — в `metrics.json` прогона.

## Прогон

`transcriber bench-diar --label current-main [--set key=value …] [--note …]` — `--set` как у `bench`
(в метрику влияют `speaker_similarity`, `min_embed_s` — реплики короче него исключаются и из кластеризации, и из метрики;
эмбеддинги записаны при встрече с тогдашним порогом, так что опустить его стенд не может — только поднять; `talk_*`). Каталог прогона: `metrics.json` (итог и строка на сессию, с именами —
файл лежит в каталоге данных), `config.yaml`, `commit.txt`, `note.txt` при `--note`. После прогона печатается таблица всех
прогонов, как у `bench`: `прогон · сессий · реплик · чистота · цельность · кластеров/говоривших · склеек · расколов`.

## Не делаем

- Не трогаем `state.json`, Raw и вольт; не вызываем `learn`.
- Не используем библиотеку голосов: стенд меряет кластеризацию, а не подпись имён.
- Разрез кластеров и свип порогов — тикеты 03 и 04, они уже на этом стенде.

## Проверка

Базовая линия по текущему конфигу: таблица с одной строкой `00-current-main`; тесты на синтетических данных
(эмбеддинги one-hot, вымышленные имена); реальные имена в репо не попадают.
