# Разделение программы и данных установки — спецификация (тикет 12)

Владислав, 14.10.2026: «файлы, которые используются как база знаний, данных, слепков голосов, должны быть
отдельны от ПО, которое записывает транскрибации встреч». Сейчас репо `~/Claude/transcriber` держит и код,
и данные установки; граница проходит по `.gitignore` («большие бинарники»), а не по признаку «персональное».
В итоге в коде и истории git лежат имена коллег, окна приватных встреч, хосты Толка, глоссарий, лог качества с темами встреч.

## Цель

Репо содержит только программу: код, тесты, документацию по устройству, примеры конфигов с вымышленными
значениями. Всё, что описывает установку Владислава, живёт в каталоге данных вне репо. После переноса
история git переписывается с нуля (решение Владислава 14.10: «удали историю»), чтобы персональное не
осталось в прошлых коммитах.

## Каталог данных

`~/Library/Application Support/Transcriber/` (переменная `TRANSCRIBER_DATA` переопределяет; тесты ставят tmp):

| Файл / папка | Сейчас | Кто читает |
|---|---|---|
| `config.yaml` (воркер: owner_*, talk_shared_names, пороги) | `worker/config.yaml` | воркер |
| `app-config.json` (privacy, recon, talk) | корень репо, в .gitignore | приложение |
| `glossary.txt` | корень репо | воркер (промпт whisper) |
| `sessions/`, `voices/`, `bench/` | корень репо, в .gitignore | воркер, стенд |
| `quality-log.md`, `quality-backlog.md` | `docs/` | рутина `/daily` вольта (шаг 9а), ручная сессия разбора |
| логи | `~/Library/Logs/transcriber-*.log` | без изменений |

В репо остаются `worker/config.example.yaml`, `app-config.example.json`, `glossary.example.txt` с
нейтральными значениями: владелец «Owner», окна приватности пустые, хосты встреч пустые, `talk_shared_names`
пустой. Умолчания в коде (`Config`, `PrivacyRules.defaults`, `TalkConfig`) тоже нейтральные: ни одного
реального имени, хоста или расписания.

## Что меняется в коде

- `worker/transcriber/config.py`: `DATA_DIR` вместо `ROOT`-производных путей; `load_config` читает
  `DATA_DIR/config.yaml` и `DATA_DIR/glossary.txt`; `sessions_dir`, `voices_dir`, `bench_dir` по умолчанию под `DATA_DIR`.
- Приложение: `PrivacyRules.defaultURL` и `SessionStore.root` под тем же каталогом; `PrivacyRules.defaults`
  без расписания приватных встреч; хосты Толка только из `app-config.json`.
- `scripts/install-worker.sh`, `scripts/build-app.sh`, оба plist: пути к каталогу данных; `build-app.sh`
  проверяет незавершённые записи по новому пути.
- Тесты: вымышленные владелец, хосты, имена; фикстуры указывают `TRANSCRIBER_DATA` на tmp.
- Документация: `README` раздел «Где лежат данные»; `docs/specs/2026-09-15-transcriber-design.md` — пометка
  о переезде; `docs/product/integrations.md` — новые пути.

## Первичная настройка и настройки (Владислав, 14.10, ревью в Lavish)

После установки из репо базовые поля заполняются сами и их можно менять:

- `transcriber init` создаёт каталог данных из примеров и спрашивает минимум: имя владельца, его имя в Толке,
  путь к вольту для рабочих записей (папки Raw и MTG), путь для приватных записей, хосты встреч. Остальное
  берётся из примеров; повторный `init` не перезаписывает существующие файлы.
- Меню приложения: пункт «Настройки…» с теми же полями плюс расписание приватности и приватные приложения.
  Правка пишет в `app-config.json` и `config.yaml`; воркер перечитывает конфиг на следующей сессии, приложение —
  сразу.
- Информация о спикерах остаётся в библиотеке голосов (владелец копится сам, коллеги из Толка, `transcriber learn`);
  в настройках только имя владельца и список общих микрофонов.
- Пороги распознавания и диаризации остаются в файле, не в меню.

## Миграция (без потери данных)

1. Остановить воркер и приложение (не во время записи).
2. Создать каталог данных, перенести `sessions/`, `voices/`, `bench/`, `config.yaml`, `app-config.json`,
   `glossary.txt`, `quality-log.md`, `quality-backlog.md`. Переносом (`mv`), не копией.
3. Выкатить код, переустановить агенты, проверить тестовую запись и `transcriber voices`.
4. Вычистить имена из документов, которые остаются в репо (спеки, планы, тесты).
5. Переписать историю: новый корневой коммит текущего состояния (`git checkout --orphan`), старая история
   удаляется; перед этим `git bundle` старой истории в каталог данных на случай отката.

## Не делаем

- Удалённый репозиторий — отдельное решение после переписывания истории.
- Изменение формата сессий, профилей и логов.

## Проверка

- `git grep` по репо не находит ни одного имени коллег, хоста компании, расписания приватных встреч.
- Полный набор тестов зелёный; приложение и воркер работают из нового каталога данных на тестовой записи.
- `/daily` шаг 9а дописывает лог по новому пути.
