# Transcriber

Локальный транскрибатор встреч: пишет микрофон и системный звук, распознаёт речь на своём компьютере и кладёт полный транскрипт (Raw) в вольт Obsidian. Устройство системы описано в `docs/agents/architecture.md`; здесь — установка и то, что меняют под себя.

## Установка

1. **Воркер.** `scripts/install-worker.sh` — ставит зависимости (uv) и launchd-агент воркера из шаблона `launchd/worker.plist`.
2. **Каталог данных.** `cd worker && uv run transcriber init` — создаёт каталог данных из примеров и спрашивает минимум: имя владельца, его имя в Толке, путь к вольту (папки Raw и MTG), путь для приватных записей, хосты встреч. Флаги для запуска без вопросов: `--yes --owner --owner-talk-name --vault --private-dir --hosts`. Повторный запуск существующие файлы не перезаписывает.
3. **Приложение.** `scripts/build-app.sh` — собирает `Transcriber.app`, подписывает локальным сертификатом «Transcriber Dev», кладёт в `~/Applications` и ставит launchd-агент приложения. Если идёт запись, скрипт откажется; `--force` перекрывает отказ.
4. **Разрешения macOS.** При первом запуске выдай приложению доступ к микрофону, к записи системного звука и к универсальному доступу (Толк читается через него).

Оба скрипта подставляют в шаблоны `launchd/*.plist` домашний каталог (`__HOME__`), путь к репозиторию (`__REPO__`) и префикс меток (`__LABEL_PREFIX__`) и пишут результат в `~/Library/LaunchAgents/<префикс>.app.plist` и `<префикс>.worker.plist`.

**Префикс меток** — обратный домен, из него же bundle id приложения. По умолчанию `local.transcriber`; свой задают строкой `LABEL_PREFIX=com.example.transcriber` в `install.env` каталога данных (или переменной `TRANSCRIBER_LABEL_PREFIX` при запуске скриптов). Разрешения macOS (микрофон, запись звука, универсальный доступ) привязаны к bundle id: на работающей установке префикс не меняют, иначе разрешения придётся выдать заново, а старые агенты — снять `launchctl bootout`. Скрипт воркера напомнит про `transcriber init`, если каталог данных ещё не настроен.

## Где лежат данные

Всё, что описывает установку, живёт вне репозитория: `~/Library/Application Support/Transcriber/`. Переменная окружения `TRANSCRIBER_DATA` переопределяет путь (так же делают тесты). launchd-агенты используют только каталог по умолчанию — `TRANSCRIBER_DATA` они не читают.

| Файл / папка | Что это |
|---|---|
| `config.yaml` | настройки воркера: владелец, общие микрофоны, пути, пороги распознавания и диаризации |
| `app-config.json` | настройки приложения: приватность (приложения, окна), хосты встреч, параметры Толка |
| `glossary.txt` | термины и имена для подсказки распознаванию, по слову на строку |
| `.env` | секреты (например `HF_TOKEN`) |
| `sessions/` | папки сессий с сырым звуком и состоянием, пока их обрабатывает воркер |
| `voices/` | библиотека голосов |
| `bench/` | стенд качества: эталонные записи и прогоны |
| `quality-log.md`, `quality-backlog.md` | лог качества и бэклог улучшений |

Логи лежат отдельно: `~/Library/Logs/transcriber-*.log`.

Основные поля меняются в приложении: пункт меню «Настройки…» (владелец, его имя в Толке, путь к вольту, путь к приватным записям, хосты встреч, приватные приложения и окна). Он правит `app-config.json` и `config.yaml`; воркер перечитывает конфиг при старте следующей сессии, приложение — сразу. Пороги распознавания и диаризации в меню нет: они только в `config.yaml`. Так же только в `config.yaml` правится заголовок раздела мыслей владельца (`owner_thoughts_heading`): рутины вольта ищут его дословно, поэтому ни «Настройки…», ни `transcriber init` его не переписывают.

## Установка под себя

1. **Владелец.** Имя владельца, его имя в Толке, вольт и путь для приватных записей задаёт `transcriber init` или «Настройки…». Остальное владельческое — в `config.yaml` каталога данных: `owner_thoughts_heading` (заголовок раздела «мысли владельца» в заметке встречи), `owner_autolearn` и `owner_min_samples` (автообучение профиля голоса).
2. **Общие микрофоны.** `talk_shared_names` в `config.yaml` — имена из Толка, которым нельзя верить как говорящим: переговорки и общие устройства. Имя владельца в Толке добавляется сюда само.
3. **Словарь.** `glossary.txt` в каталоге данных — термины и имена, которые распознавание должно писать верно (по слову на строку). Образец — `glossary.example.txt` в репозитории.
4. **Хосты встреч и приватность.** В `app-config.json` ключ `privacy` задаёт приложения и окна, которые пишутся как приватные: без имён, без обучения голосов, файл лежит вне вольта. Пока хосты встреч не вписаны, звонок в браузере на корпоративном хосте вообще не распознаётся как встреча: карточки нет, ничего не пишется, а в логе приложения — «browser mic without a meeting tab» (браузер держит микрофон, но вкладки встречи нет). Об этом же при запуске предупреждает строка `privacy: workHosts пуст` в логе.
5. **Голоса.** Каталог `voices/` в каталоге данных на старте пуст. Профиль владельца набирается сам по чистому микрофону и созреет примерно за 3 встречи (по 10 отпечатков с каждой, порог 30); пока он не созрел, весь микрофон — «Me». Сколько отпечатков накоплено, покажет `transcriber voices` (поле `count`); после порога `owner_min_samples` гость в переговорной на микрофоне получает свою метку, а в шапке Raw появляется «На микрофоне кроме владельца».
